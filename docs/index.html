File4Base Documentation

File4Base is a modern, open-source rapid application database platform for rapid development. Built with Go (Clean Architecture, DBAL) on the backend and Flutter (Desktop & Web Client) on the frontend.

⚡
Multi-Engine DBAL

PostgreSQL 16 default engine with optional MariaDB/MySQL support, dynamic DDL migrations, and live catalogs.

🎨
Visual Database Studio

Full-screen visual layout designer with 16 drawing tools, 8-handle resizing, inspector palette, and draggable parts.

🔒
Database-Scoped Security

Strict catalog-level user isolation, bcrypt password hashing, granular layout permissions, and protected unauthenticated workspace.

📦
Self-Contained .f4p Bundles

MessagePack-packaged database solutions with tables, columns, layouts, scripts, and users with auto-save support.

🚀 Quick Start with Docker

Run the full File4Base stack with a single Docker Compose command:

# 1. Clone repository
git clone https://github.com/file4base/file4base-app.git
cd file4base-app

# 2. Launch database, backend API, and File4Base Web Client
docker compose up -d

# 3. Access web client
open http://localhost:3000

The stack exposes:

  • File4Base Web Client: http://localhost:3000 (served via Nginx)
  • Backend Core API: http://localhost:8080 (REST & WebSockets)
  • OpenAPI / Swagger UI: http://localhost:8080/swagger
  • PostgreSQL 16: localhost:5432 (database: file4base_dev)

📋 The 4 Operational Modes

File4Base mirrors the classic 4-mode operational state machine:

1. Browse Mode (Cmd/Ctrl + B)

Default interactive data view. Navigate records with standard slider controls, create, duplicate, and delete records, sort columns, and edit layout fields with live validation.

2. Find Mode (Cmd/Ctrl + F)

Enter search criteria directly into form fields. Supports operators like =, >, <, ... (range), and text searches to filter the active found set.

3. Layout Mode Studio (Cmd/Ctrl + L)

The File4Base studio workspace includes:

  • Top Ribbon Palette: Selection pointer, Text tool, Line, Rectangle, Rounded Rectangle, Oval, Field tool, Button, Popover Button, Button Bar, Tab Control, Portal, Chart, Web Viewer, and Part tool.
  • Left Fields & Objects Pane: Drag & drop database columns straight onto the canvas, filter fields, customize placement orientation and control types.
  • Draggable Canvas Parts: Real-time draggable divider bars for Header, Body, and Footer with live point height badges and 8-handle object resizing.
  • Right Inspector (4 Tabs): Geometry coordinates, Fill/Border styles, Data bindings, and Typography.
  • Exit Layout Button: Green-accented button to save changes and return seamlessly to Browse mode.

4. Preview & Print Mode (Cmd/Ctrl + U)

WYSIWYG print preview simulating pagination, margins, page setup, and PDF export.

🗄️ Manage Database & Schema

Accessed via File > Manage > Database...:

  • Tables Tab: Create, rename, duplicate, empty, or delete tables. All mutations update physical database tables and sync to sys_tables.
  • Fields Tab: Add typed columns (Text, Number, Date, Time, Timestamp, Container, Calculation, Summary).
  • Relationships Graph: Visual node canvas with drag-and-drop relationship links, table occurrences, and cascade rules.

🧮 Calculations & Formulas

Calculation fields evaluate dynamically on record insert or update using an embedded formula parser.

// Example: Total with tax calculation
Price * Quantity * 1.21

// Example: Full name concatenation
FirstName & " " & LastName

⚙️ Script Workspace

Automate business workflows using visual block steps:

  • Navigation: Go to Layout, Go to Record, Go to Field.
  • Editing: Set Field, New Record, Delete Record.
  • Logic: If, Else If, Else, End If, Loop, Exit Loop If.
  • Execution: Run Script, Pause/Resume, Exit Script.

🛡️ Security & User Accounts (v0.4.18)

Security is strictly catalog-isolated:

  • Per-Database Accounts: Accounts belong exclusively to their respective database and solution file.
  • Roles: owner (full schema & security control), admin (table & layout editing), user (data browse/find only).
  • Granular Layout Permissions: Assign Read-Write, Read-Only, or No Access per layout.
  • Protected Workspace Lock: Cancelling authentication immediately locks the application and purges in-memory tables and records.

💡 Service & Support — Working with GitHub Issues

Community & Support Guidelines
We welcome bug reports, feature suggestions, and pull requests! Please follow these best practices to ensure fast triage and resolution.
  1. Search Before Creating: Visit GitHub Issues and search existing open and closed issues before submitting a new one.
  2. Use Clear Descriptive Titles: Prefix your issue title with tags like [Bug], [Feature], [Documentation], or [Desktop] (e.g. [Bug] Layout divider handle snaps incorrectly on Safari).
  3. Provide Reproduction Steps: Include exact steps: 1) Open Solution, 2) Switch to Layout Mode, 3) Resize part divider.
  4. Include Environment Details: Always state:
    • File4Base Version: (e.g. v0.4.18)
    • Operating System: macOS (Apple Silicon / Intel), Windows 11, Ubuntu 24.04, or Web Browser (Chrome/Firefox/Safari).
    • Database Engine: PostgreSQL 16 or MariaDB 11.
  5. Attach Logs & Screenshots: Attach server logs (docker logs file4base-api) and browser console or terminal stack traces.
