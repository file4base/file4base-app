File4Base Documentation

File4Base (v0.15.2) is a modern, open-source rapid application database platform. Built with Go (Clean Architecture, multi-engine DBAL, REST API v1) on the backend and Flutter (macOS, Windows, Linux Desktop & File4Base Web Client) on the frontend.

⚡
Multi-Engine DBAL

PostgreSQL 16 default engine with optional MariaDB/MySQL support, external SQL data sources, dynamic DDL migrations, and live system catalogs.

🎨
Visual Database Studio

Full-screen visual layout designer with 16 drawing tools, Formatting Bar, Text Ruler, Page Margins, Portals, Charts, Web Viewers, and Layout Themes.

🔒
Security, MFA (2FA) & Kiosk Mode

Database-scoped accounts, Google Authenticator TOTP 2FA, login rate limiting, AES-256-GCM transport encryption, and full Kiosk Mode runtime lockout.

🛠️
Server Tools & Packaging

9-module Server Administration Console (Backups .tar.gz, Container Update Watcher, ACME TLS, Live Telemetry, Cron) plus .f4p & .f4data bundles.

🚀 Quick Start with Docker

Run the full File4Base stack with a single Docker Compose command:

# 1. Clone repository
git clone https://github.com/file4base/file4base-app.git
cd file4base-app

# 2. Launch database, backend API, and File4Base Web Client
docker compose up -d

# 3. Access File4Base Web Client
open http://localhost:3000

The stack exposes:

  • File4Base Web Client: http://localhost:3000 (served via Nginx with reverse proxy to API & Swagger)
  • Backend Core API (v1): http://localhost:8080/api/v1 (107 REST endpoints)
  • OpenAPI 3.0.3 / Swagger UI: http://localhost:3000/swagger/ and http://localhost:8080/swagger/
  • Health & Readiness Probes: /healthz, /livez, /readyz, /startupz
  • PostgreSQL 16: localhost:5432

📦 Solutions (.f4p) & Data Bundles (.f4data)

File4Base separates structural design from user records so you can version, clone, and transport solutions cleanly:

  • Export Solution (.f4p): Packages tables, columns, calculations, summaries, table occurrences (with Relationship Graph coordinates), relationships, value lists, layouts, scripts, custom menu sets, file options, and accounts/permissions.
  • Export Database Data (.f4data): Packages all table rows across the database into a portable data archive.
  • Roundtrip Import: From File > Open Solution... (or File > Import Data (.f4data)...), select a .f4p solution file and an optional companion .f4data file to provision a new database or restore onto an existing database with automatic layout/startup ID remapping.
  • Save a Copy as XML & DDR: Export human-readable XML representations (Tools > Save a Copy as XML...) or generate a full HTML/JSON/Markdown Database Design Report (Tools > Database Design Report...).
  • Structure Clipboard: Copy and paste tables, fields, layouts, and scripts across solutions (Tools > Structure Clipboard...) with dependency conflict preview.

🔄 FileMaker XML/HTML DDR & .fmp12 Migration

Migrate existing FileMaker solutions via File > Migrate from FileMaker... (Migration Guide):

  • XML & HTML DDR Parser: Extracts base tables, typed fields, calculation & summary formulas, table occurrences, pair-keyed relationships, value lists, scripts, and multi-part layouts (including Portals, Group Buttons, Merge Fields, and Web Viewers).
  • Binary .fmp12 Record & Container Extractor: Pair your DDR with the binary .fmp12 file to extract table rows, relational keys, and embedded JPEG/PNG CONTAINER images directly into a new File4Base database.

📋 The 4 Operational Modes

File4Base provides a 4-mode operational state machine accessible from the View menu and top mode switcher:

1. Browse Mode (Cmd/Ctrl + B)

Interactive data entry and navigation across three synchronized views:

  • Form View: Single-record canvas rendering custom layouts, interactive value list controls (drop-down lists, pop-up menus, radio button sets, checkbox sets), related fields, portals, tab controls, slide controls, charts, web viewers, and container media. Single-click any field (including currency/date formatted fields) to type and auto-save to PostgreSQL/MariaDB.
  • List View: Vertically scrolling record bands with inline field editing on the active record, or grouped sub-summary & grand-summary report views.
  • Table View: Spreadsheet grid allowing direct inline cell editing, column sorting, and quick record creation.

2. Find Mode (Cmd/Ctrl + F) & Saved Finds

Build multi-request queries directly on layout fields:

  • Operators: Exact match (=, ==), range (100...500, 2026-01-01...2026-12-31), inequalities (>, >=, <, <=, !=), wildcards (*, @, ?), and today's date token (//).
  • Multi-Request OR & Omit: Add multiple Find requests (Requests > Add New Request) for OR logic, or mark a request as Omit to exclude matching records.
  • Relational Finds & Saved Finds: Enter criteria into related fields or portals, and save complex queries under Saved Finds for 1-click reuse.

3. Layout Mode Studio (Cmd/Ctrl + L)

Full-featured WYSIWYG layout designer:

  • 16 Studio Tools: Selection pointer, Text label, Line, Rectangle, Rounded Rectangle, Oval, Field tool, Button, Popover Button, Button Bar, Tab Control, Slide Control, Portal, Chart, Web Viewer, Part tool, Set Tab Order, and Format Painter.
  • Left Fields & Objects Dock: Drag & drop database columns straight onto the canvas; newly created fields in Manage > Database are also placed automatically onto the default Form layout.
  • Layout Parts: Header, Sub-summary (when sorted by...), Body, Leading/Trailing Grand Summary, and Footer with draggable height dividers.
  • Right Inspector (4 Tabs): Position/Autosizing anchors, Appearance/Styles & Layout Themes, Data bindings/Value Lists/Display Formats, and Script Triggers.

4. Preview & Print Mode (Cmd/Ctrl + U)

Paginated WYSIWYG print preview supporting multi-column mailing labels (e.g., Avery L7160), form letters with <<Merge Fields>> and system tokens ({{CurrentDate}}, {{PageNumber}}, {{RecordNumber}}), sub-summary reports, and native PDF generation.

✨ Edit, View & Format Menus

  • Edit Menu: Full support for Undo, Redo, Cut, Copy, Paste, Clear, and Select All across both Browse/Find text fields (via EditMenuFocusTracker) and Layout Mode canvas objects.
  • View > Formatting Bar: Quick-access horizontal toolbar for font family, font size, bold/italic/underline/strikethrough, text/fill/border colors, alignment, line spacing, and number/date/conditional format dialogs.
  • View > Text Ruler & Page Margins: Interactive graduated ruler (pt / in) with draggable left/right paragraph indents and clickable tab stops, plus printable page margin overlays.
  • Format Menu: Non-destructive display formatting for Number... (Currency, Percent, Decimal, Thousands separator, Negative red/parentheses), Date..., Time..., Timestamp..., Text... case transforms, and Conditional... formatting rules.

🗄️ Manage Database, Relationships & Portals

Accessed via File > Manage > Database...:

  • Tables & Fields Tabs: Create physical tables and typed columns (Text, Number, Date, Time, Timestamp, Boolean, Container, Calculation, Summary) with auto-enter serials, defaults, and field validation rules.
  • Relationships Graph & Table Occurrences: Visual node canvas connecting table occurrences with =, !=, <, <=, >, >=, or Cartesian predicates, cascade delete, and "Allow creation of records in this table via this relationship".
  • Portals & Related Fields: Place related fields (Companies::company_address) directly on a parent layout, or draw multi-row Portals with custom sort orders, vertical scrolling, related record deletion, and inline related record creation via the trailing blank portal row.

🧮 Calculations, Summary Fields & Reports

Calculation fields evaluate dynamically using the built-in formula engine, while Summary fields aggregate across the active found set and break groups:

// Conditional Annual Fee calculation
If ( customer_type = "New" ; 200 ; 100 )

// String & Math expressions
Upper ( Trim ( first_name & " " & last_name ) )

Summary Reports & Charts: Combine Summary fields (Total of, Average of, Count of, Minimum, Maximum) with Sub-summary layout parts and Column, Bar, Line, Area, Pie, or Scatter Charts to build live executive dashboards and grouped financial reports.

⚙️ Script Workspace, Debugger & Data Viewer

Automate workflows using visual script steps and inspect execution in real time:

  • Navigation & Modes: Go to Layout, Go to Record/Request/Page, Go to Field, Enter Browse Mode, Enter Find Mode, Enter Preview Mode.
  • Records & Fields: Set Field, Set Variable ($local and $$global), New Record/Request, Duplicate Record/Request, Delete Record/Request, Commit Records/Requests, Revert Record/Request.
  • Found Sets & Windows: Perform Find, Show All Records, Show Omitted Only, Omit Record, Sort Records, Adjust Window (Restore, Maximize, Minimize, Resize to Fit), Refresh Window.
  • Control Flow & Session: If / Else If / Else / End If, Loop / Exit Loop If / End Loop, Perform Script, Pause/Resume Script, Exit Script, Show Custom Dialog, Re-Login, Close File, Exit Application.
  • Script Debugger & Data Viewer: Step through scripts line by line (Tools > Script Debugger) and evaluate live fields, variables, and calculation expressions in the Data Viewer (Tools > Data Viewer).

🖥️ Kiosk Mode & Developer Utilities

Configure dedicated touchscreens and locked-down user deployments via Tools > Developer Utilities... (Specification):

  • Full Interface Lockout: Hides the top Menu Bar, Formatting Bar, Text Ruler, Left Status Sidebar, and Bottom Status Bar, and blocks developer keyboard shortcuts (Cmd+L, Cmd+N, Cmd+O, Cmd+S).
  • Conditional Privilege: Accounts with [Full Access] (owner / admin) or layout/script modification privileges open the database normally for development; non-admin accounts automatically enter Kiosk lockout. Includes a 1-click "Test Kiosk Mode Now (Simulate Non-Admin)" preview.
  • Primary Home Layout & Readiness Auditor: Configure the Primary/Home Layout, force credential login on open, audit secondary layouts for dead-ends, and auto-inject Home, Re-Login, and Exit Kiosk script buttons.
  • Preview Mode Auto-Return: Automatically pauses in Preview Mode for a configurable countdown (e.g., 10 seconds) and returns to Browse Mode so Kiosk users are never stranded on a print preview screen.

🖧 Server Tools & Administration Console (9 Modules)

Accessible from the top-level Server Tools menu for server administrators (Specification):

  1. Containers & Services (with Automatic Update Watcher): Inspect live health, version, uptime, CPU/RAM usage, and container logs for file4base-api, file4base-web, and file4base-postgres. Checks GitHub Releases & Docker Hub for newer versions, displays an "Update Available" badge in the menu/status bars, and performs 1-click "Pre-Backup & Update Now".
  2. Backups & Snapshots: Create on-demand snapshots in ./data/backups/, download archives as .tar.gz, upload external backup archives (.tar.gz / .f4b.json), and execute full point-in-time DDL + DML + Layout restoration.
  3. Domain & SSL/TLS Certificates: Configure public domain, automatic Let's Encrypt / ZeroSSL ACME certificate provisioning (http-01 / tls-alpn-01), or upload custom PEM certificate chains.
  4. API Telemetry & Live Metrics: Rolling 60-minute ring buffer with live Requests Per Minute (RPM) bar charts, Average vs P95 latency line charts, HTTP status breakdown, Go runtime heap/goroutines, and top endpoints.
  5. Connected Clients & Sessions: View active user sessions across databases with 1-click session revocation (Force Disconnect).
  6. Scheduled Tasks & Cron Scripts: Automate recurring database backups and server-side script runs using standard cron expressions.
  7. Audit & Security Logs: Filterable immutable security event trail across authentication, MFA, backups, TLS, container actions, and maintenance.
  8. Database Maintenance & Optimizer: Inspect per-table column/row counts and trigger VACUUM ANALYZE, ANALYZE, and REINDEX DATABASE.
  9. Server Notifications, SMTP & Webhooks: Configure outbound SMTP email and Slack/Discord/Teams/Generic JSON webhooks with test dispatch.

🛡️ Security, RBAC & Multi-Factor Authentication (v0.15.2)

Security is strictly catalog-isolated and hardened across transport and authentication layers:

  • Per-Database Accounts & Roles: Accounts belong exclusively to their database (owner, admin, user) with bcrypt password hashing and brute-force rate limiting on sign-in and database drop operations.
  • Google Authenticator MFA / 2FA (RFC 6238 TOTP): Enable 2FA for any account in File > Manage > Security... by scanning the generated QR code with Google Authenticator, Authy, or 1Password and verifying a 6-digit TOTP code.
  • Granular Table, Layout & Extended Privileges: Assign Read-Write, Read-Only, or No Access per table and layout, and toggle role capabilities such as bulk_export and bulk_import.
  • AES-256-GCM Encrypted Channel: Optional payload-level authenticated encryption between the Web/Desktop client and the Go API via /api/v1/crypto/handshake.

📋 Latest Releases & Changelog

Release v0.15.2 (2026-10-16)

Fixed

  • Real-time sync never connected in the deployed server (WebSocket upgrade failed with 501 Not Implemented). The global telemetry/logging middleware wraps every response in a status-recording writer, but that wrapper embedded http.ResponseWriter without forwarding Hijack, so it did not satisfy http.Hijacker. The WebSocket upgrade at GET /api/v1/realtime needs to hijack the connection, so it was refused for every client — each browser only ever saw its own edits and picked up others' changes solely on a manual reload or when navigating between records (the database was always shared; only the live push was broken). The wrapper now forwards Hijack (and Flush). This passed the unit tests before because they mount the API router without the production middleware stack; added a telemetry test that the wrapped writer supports hijacking.

Release v0.15.1 (2026-10-16)

Security

  • Dependency and Go toolchain updates to clear all known vulnerabilities (server/go.mod, server/go.sum). govulncheck ./... reported 23 called vulnerabilities (Go standard library plus github.com/go-chi/chi/v5); it now reports 0. The build toolchain is pinned to go1.26.9 (new toolchain directive, keeping the go 1.26.0 minimum), github.com/go-chi/chi/v5 is updated 5.2.1 → 5.5.0 (fixes the host-header/open-redirect in RedirectSlashes and the request-parsing advisories GO-2026-5774/5775/5777), and golang.org/x/net is updated 0.58.0 → 0.61.0 (fixes GO-2026-6603/6610/6611/6612/6617). One advisory remains and is accepted: GO-2026-5932 (the unmaintained golang.org/x/crypto/openpgp package) has no fixed version, and File4Base neither imports nor calls it.
  • The audit log, session list and login throttle no longer trust a client-supplied IP by default. X-Forwarded-For / X-Real-IP were honored from any caller (and chi's middleware.RealIP rewrote RemoteAddr from them unconditionally), so a direct client could forge the address recorded against it — or, since the login throttle keys on that address, interfere with another account's lockout state. Those forwarding headers are now trusted only when the request's direct TCP peer is a configured reverse proxy, set via the new FILE4BASE_TRUSTED_PROXIES setting (comma-separated IPs and CIDR ranges); the real client is then recovered by walking X-Forwarded-For right-to-left past trusted hops. With no trusted proxies configured (the default) the direct peer address is always used. The resolution is shared by the audit/session metadata, the request telemetry log and the login-throttle key (new internal/clientip package). Documented in .env.example and docs/api/API_REFERENCE.md.
  • Hardening from a review of the file importers, the encrypted channel and the control store (documented in docs/specs/security_model.md). The encrypted payload channel (server/internal/crypto) now (a) logs a startup warning when FILE4BASE_CHANNEL_SECRET is unset — the fallback key is a public built-in default that provides no confidentiality on its own — and (b) caps the in-memory read of an encrypted request body at 512 MiB so a hostile oversized payload cannot exhaust server memory. The review confirmed the .fmp12 / HTML-DDR importers whitelist ([a-z0-9_]) and quote every imported identifier and bound every binary read against the input length (no SQL injection, no out-of-bounds), and that the SQLite control store is fully parameterised with transactional writes; those needed no code change.

Fixed

  • Saving a script now runs inside a database transaction, so a failing step can no longer corrupt it (server/internal/schema/script_service.go). CreateScript and UpdateScript wrote the script row and each of its steps as separate statements; UpdateScript first deleted all existing steps and then re-inserted the new ones one at a time. A failure partway through (for example a step violating a column constraint) left the script with its steps wiped out and only a prefix of the new sequence written — and CreateScript could leave a half-created script. Both now wrap the whole operation in a single transaction that rolls back on any failure, leaving the previously stored script untouched. Added internal/schema tests that a failing step rolls back both the create and the update.

Changed

  • Audited and annotated the client's unhandled async futures (client/lib, 135 discarded_futures / unawaited_futures from flutter analyze, now 0). The audit found that the flagged fire-and-forget calls target methods that already surface their own failures to the user (an error SnackBar, an in-dialog error state, or a _report(...)) or are benign lifecycle cleanup (cancel() / close()); none was silently swallowing an error in a user-facing flow. Each is now wrapped in unawaited(...) (the idiom already used in the codebase) so the intentional discard is explicit — behaviour is unchanged, errors still reach the zone handler, and the lint is cleared. All 427 Flutter tests pass. (The only remaining findings are in test files and are benign.)

Release v0.15.0 (2026-10-16)

Added

  • Super-owner accounts: a per-account super_owner flag that grants full, server-wide control independent of the database a session signed in to — the account-based way to administer the whole server, alongside the FILE4BASE_ADMIN_DATABASE setting (an owner of that database is still a server administrator, for backward compatibility). A super-owner reaches every Server Tool of every database. The first super-owner is bootstrapped with FILE4BASE_SUPER_OWNER=database:username (comma-separated for several); a seeded account signs in as a super-owner even before any flag is stored, so it can then grant the privilege to other owners. Grant/revoke with PUT /api/v1/security/users/{id}/super-owner (super-owners only; the target must be an owner; a super-owner cannot strip their own privilege). Manage Security shows a shield control on owner rows for super-owners. Changing the flag re-stamps the account, so the target's existing sessions end at once.
  • Real-time sync (server): a change-notification WebSocket at GET /api/v1/realtime. A client authenticates with its bearer token as the first message and then receives a small event ({type, resource, database, origin}) whenever the records or schema of its database change in another session — so every open window can reload instead of going stale. Events carry no record data (the client reloads what it shows) and are scoped to the client's database; the origin id lets a client ignore the changes it made itself. In-memory per process (a future multi-replica setup would use Postgres LISTEN/NOTIFY). The Flutter client subscribes to it (below).
  • Real-time sync (client): while signed in, the app keeps a WebSocket to /api/v1/realtime (auto-reconnecting). When another session changes the table you are viewing, Browse reloads and keeps you on the same record — and it waits until you leave a field so it never interrupts your typing; schema/layout changes reload the tables and layouts. The app ignores the changes it made itself.
  • Server Tools: a backup file (.tar.gz or .f4b.json) can be uploaded (POST .../backups/upload, "Upload Backup..." button) and stored as a server-side backup, then restored — the counterpart of download. A non-administrator's upload can only ever target their own database.

Release v0.14.0 (2026-10-15)

Added

  • Server Tools: a backup can be downloaded as a gzip-compressed tar (.tar.gz, GET .../download?format=targz) and saved to disk; the window's download button now saves the file (a separate button still copies the JSON to the clipboard).

Security

  • Server Tools could be used to read and change other databases and to control the whole server. Every /api/v1/server/* route only required the admin role of some database, and by default anyone who can reach the server can create a database and become its owner. Such an account could back up, download and restore any other database, list and revoke every session, read and clear the audit log, change TLS and restart or update the containers. Now
  • External data sources could be made to write. Reading a source with a statement only checked that it began with SELECT or WITH and held no ;, and anyone with the bulk_import capability could send one, run with the credentials the owner stored. SQL Server accepts a write after WITH, several statements without ;, and SELECT … INTO creates a table. Now
  • No limit on password guessing. Sign-in (POST /api/v1/auth/login) and credential-based database drops accepted unlimited password attempts. Now a database + username + client is locked out (429 Too Many Requests, with Retry-After) after FILE4BASE_LOGIN_MAX_ATTEMPTS failures in a row (default 10), for FILE4BASE_LOGIN_LOCKOUT_SECONDS (default 15 min). A missing second factor does not count; a success clears the counter. Keyed on the client address too, so one attacker cannot lock a victim out.

Release v0.13.1 (2026-10-15)

Fixed

  • Browse mode: one click on a field now puts the cursor in it, ready to type. It took two: every field was treated as formatted (unset number/date/time formats and the default text case none counted as formatting), and a formatted field was rebuilt as a new text field when focused, so it got the focus but no text input until a second click.
  • Browse mode, List and Table views: one click on a field of another record makes it the current record and starts editing that field. The field was focused before the record changed, and the double click on the whole row (open in Form view) delayed every single click; it moved to the record number (Table) and an open button at the end of each row (List).
  • Server Tools reported a hard-coded stack version (0.13.0) that scripts/bump_version.sh does not update, so after an upgrade it showed the old version and a stale "update available". The server now reports its own version (AppVersion, passed as api.Options.Version; FILE4BASE_VERSION still overrides it) and the client uses its single version constant.
  • Client tests: refreshed the shared new-database fixture (it lacked the File Options kiosk_mode key added in 0.13.0; the server stores File Options as given, so nothing was lost), and updated the Script Workspace and Browse record bar tests to the current catalog and inline-editing table.

💡 Service & Support — Working with GitHub Issues

Community & Support Guidelines
We welcome bug reports, feature suggestions, and pull requests! Please follow these best practices to ensure fast triage and resolution.
  1. Search Before Creating: Visit GitHub Issues and search existing open and closed issues before submitting a new one.
  2. Use Clear Descriptive Titles: Prefix your issue title with tags like [Bug], [Feature], [Documentation], or [Desktop] (e.g. [Bug] Layout divider handle snaps incorrectly on Safari).
  3. Provide Reproduction Steps: Include exact steps: 1) Open Solution, 2) Switch to Layout Mode, 3) Resize part divider.
  4. Include Environment Details: Always state:
    • File4Base Version: (e.g. v0.15.2)
    • Operating System: macOS (Apple Silicon / Intel), Windows 11, Ubuntu 24.04, or Web Browser (Chrome/Firefox/Safari).
    • Database Engine: PostgreSQL 16 or MariaDB 11.
  5. Attach Logs & Screenshots: Attach server logs (docker logs file4base-api) and browser console or terminal stack traces.
